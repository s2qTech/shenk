# 身刻

记录身体变化，掌控生活节奏。

这是训练与身体状态记录工具的 v2 项目设计空间。v1 是当前已经可用的单页计时器，继续保持稳定。身刻当前先把日历日志、训练建议、截图识别、天气、体重/腰围趋势和未来同步整合到一个清晰的个人工具里。计时器后续从独立项目合并。

## 项目定位

这是一个个人训练助手，不是健身社区、不是内容平台、不是医疗诊断工具。

核心任务：

- 让用户快速知道今天建议做什么。
- 让用户方便记录今天实际做了什么。
- 让用户像看日历一样回看过去训练。
- 从运动截图中提取数据，减少手工录入。
- 结合历史记录、疲劳、疼痛、天气和体重趋势给出后续建议。
- 后续合并计时器能力，随时调用训练、热身、拉伸和恢复流程。

## 是否新开项目

建议新开项目。

理由：

- v2 需要数据模型、日历、存储、AI 后端、同步和导入导出，已经超过单 HTML 计时器的范围。
- v1 继续作为稳定可用版本，避免在重构中影响日常训练。
- v2 可以逐步迁移 v1 的训练流程，成熟后再替代 v1。

推荐项目形式：

- 前端：同一套 Web 核心，适配手机和电脑。
- 手机端：优先提供 Android APK 壳，避免依赖小米/HyperOS 对 PWA 安装的支持。
- 电脑端：网页访问。
- 托管：GitHub Pages 或 Cloudflare Pages。
- 数据：先本地 IndexedDB，随后接 Supabase/Firebase 同步。
- AI：后端函数代理 OpenAI API，前端不暴露 API Key。
- 导出：JSON 为主，CSV/XLSX 为辅。

## 第一阶段 MVP

第一阶段只做本地可用版，不做账号同步。

必须包含：

- 今日建议卡片。
- 日历视图。
- 每日记录编辑。
- 体重记录。
- 手动录入运动数据。
- JSON 导入导出。
- Android 本地安装包方案验证。

可选包含：

- 当日天气自动获取。
- 上传截图后本地预览。
- 截图识别接口占位。

暂不包含：

- 云同步。
- 自动历史天气补全。
- 社交分享。
- 医疗建议。
- 多用户家庭账号。

## 第二阶段

- 接入云数据库同步。
- 接入 AI 截图识别。
- 加入趋势分析和周复盘。
- 加入 CSV/XLSX 导出。
- 加入冲突合并策略。
- 优化 Android 壳的安装、权限和更新流程。

## 第三阶段

- 进一步优化 AI 建议。
- 根据长期数据调整训练计划。
- 支持云盘备份或云盘同步。
- 支持更细的体重、腰围、睡眠和疲劳趋势。

## 设计原则

- 少打扰，低压力。
- 用户实际做了什么，比计划原本是什么更重要。
- 记录要比分析更容易。
- AI 只能建议，不能直接覆盖用户判断。
- 任何异常疼痛、麻木、胸闷、头晕都优先降级或停止。
- 数据默认属于用户，可导出、可备份、可迁移。

## 当前开发状态

当前工作区已经包含第一版无依赖静态 MVP：

- `index.html`
- `src/styles.css`
- `src/app.js`
- `PROJECT_STATE.md`
- `docs/`

因为当前环境里 `node/npm` 不在 PATH，且捆绑 Node 没有 Vite/React，第一版先按 fallback 路线实现为静态 HTML/CSS/JS。可以直接打开 `index.html` 查看；后续依赖安装可用后再迁移到 Vite + React + TypeScript。

计时器相关功能暂时不在这个 MVP 里实现，等记录功能稳定后再从独立计时器项目合并。

当前信息架构以日历为主：左侧是导航栏，日历是主区域，日历中区分实际记录、今日建议和未来预测；点击日期后从右侧滑入详情卡片。今天可直接编辑，过去日期需要点“修正”后才能改，未来日期只查看预测。JSON 导入导出只放在设置页签里。

记录编辑被分成训练记录和状态记录，两者独立保存。状态记录包含体重、腰围、昨晚睡眠、今日精力、疲劳和不适；睡眠、精力、疲劳使用同向滑块，疼痛/不适使用“无、轻微、明显、严重”的分段选择。

运动类型已接入 `assets/sports/` 下的图标资源，让日历和详情卡更清晰但不做重装饰。原来的训练概览已压缩为日历上方的 7 天节奏条，体重不放在这里。
